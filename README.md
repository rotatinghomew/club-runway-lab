# 俱乐部现金压力与合同签付顺序

金额按原币最小单位（整元），周序取 `week`。`fund=any` 是不受限，不受限余额也可以付有用途的债务；`staff` 与 `travel` 只能用于标注同用途的债务。`scenarios` 每行代表一个联合情景，概率总和为 1，标注相同结果变量的合同在同一情景下共同发生。除场馆类合同不开馆时改按 `delayed_week` 外，条件不符的合同款不发生。上下界是有效证据范围。`fx` 为每单位外币的本币元数，未有报价的未来周不能悄悄按 1 折算。合同类型 `active` 已生效、`offer` 是候选，明确的分期和延签允许组合由合同份额表示。`posted` 部分冲减原应收应付并成为已知事实；`pending` 不等同实际收付；`delayed` 仅令尚未发生的余额改到 `delayed_week`。压力判断的底线和置信要求由分析请求决定，余额不得通过受限款跨用途填平。

## 数据包

`sample/` 是本地合成的业务记录，均为 UTF-8 CSV；`table-format.json` 给出各表的列顺序与标量类型，`str` 中 `-` 表示不适用，逗号分隔多值。不同表中同名业务标识用于关联，具体含义见上文。资料入口只检查表头和格式，不对业务状态作判断。

## 运行

使用 Python 3.11 标准库，不需要安装三方依赖。读取样例与运行资料检查：

```sh
python3 intake.py
python3 -m unittest discover -s tests -v
```

也可以将同格式的资料目录作为 `intake.py` 的位置参数。
